프로젝트 소개

React2Shell (CVE-2025-55182)은 Next.js 15.0.0 버전의 React Server Component(RSC) 아키텍처에서 발견된 역직렬화 기반 원격 코드 실행(RCE) 취약점입니다. 최신 React 생태계의 내부 동작 원리를 심층적으로 분석하기 위해 진행한 취약점 연구 프로젝트입니다.

기획 의도

  • 최신 프론트엔드 프레임워크인 Next.js 내부의 RSC 역직렬화 메커니즘을 이해했습니다.
  • Server Action 처리 과정에서 발생할 수 있는 객체 주입 및 실행 흐름을 분석했습니다.
  • 실제 클라우드 및 SaaS 환경에서 적용 가능한 대응 가이드라인을 도출했습니다.

수행 역할

  • Vulnerability Analysis: Next.js 서버의 Action State 파싱 로직과 `__esModule` 속성을 활용한 객체 주입 가능성을 분석했습니다.
  • PoC Development: Node.js `child_process.exec` 호출 가능성을 검증하기 위한 `$$ACTION_ID` 연계 페이로드를 작성했습니다.
  • Verification: RCE, 서버 장애 유발(DoS), 정보 유출(Info Leak) 시나리오를 Docker 환경에서 검증했습니다.

주요 성과 및 인사이트

  • 서버 권한 탈취로 이어질 수 있는 RCE 공격 원리를 재현하고 검증했습니다.
  • RSC와 Server Actions 내부 동작 원리에 대한 기술적 이해도를 높였습니다.
  • 단순 취약점 증명을 넘어 Next.js 인프라 환경을 고려한 방어 로직을 연구했습니다.

프로젝트 소개

Spring4Shell (CVE-2022-22965)은 Spring Framework Core에서 발생한 원격 코드 실행(RCE) 취약점입니다. Spring의 데이터 바인딩 구조와 Tomcat 동작 방식을 분석하고, 실제 공격 시나리오를 재현하여 방어 전략을 정리하기 위해 수행했습니다.

기획 의도

  • Spring Core의 DataBinder 메커니즘과 객체 바인딩 흐름을 이해했습니다.
  • JDK 9 이상 환경의 classLoader 접근 제어 우회 가능성을 분석했습니다.
  • 엔터프라이즈 Java 환경에서 발생 가능한 RCE 위험과 대응 방안을 정리했습니다.

수행 역할

  • Vulnerability Analysis: `class.module.classLoader` 접근 흐름과 Spring DataBinder 처리 방식을 분석했습니다.
  • PoC Development: Tomcat `AccessLogValve` 속성 조작을 이용한 WebShell 생성 시나리오를 재현했습니다.
  • Verification: Burp Suite 기반 요청 조작으로 WAS 장악 가능성과 보안 장비 우회 가능성을 검증했습니다.

주요 성과 및 인사이트

  • Spring Boot + Java 환경에서 RCE 공격 흐름과 WebShell 악용 시나리오를 재현했습니다.
  • 프레임워크의 편의 기능이 보안 경계 붕괴로 이어질 수 있음을 코드 레벨에서 확인했습니다.
  • 패치, WAF 탐지, 입력 바인딩 제한 등 방어 관점의 대응 방안을 정리했습니다.

프로젝트 소개

Log4Shell (CVE-2021-44228)은 Java 로깅 라이브러리 Log4j에서 발견된 JNDI Injection 기반 원격 코드 실행 취약점입니다. JNDI Lookup 기능의 동작 원리와 공격 흐름을 분석하고, 탐지 및 대응 관점에서 정리한 연구 프로젝트입니다.

기획 의도

  • Log4j의 JNDI Lookup 기능이 원격 코드 실행으로 이어지는 원리를 분석했습니다.
  • LDAP/RMI 프로토콜을 활용한 원격 객체 로딩 및 역직렬화 흐름을 이해했습니다.
  • 우회 페이로드와 탐지 로직을 비교하며 실무형 방어 관점을 정리했습니다.

수행 역할

  • Vulnerability Analysis: Log4j `PatternLayout`과 문자열 치환 로직을 분석했습니다.
  • PoC Development: 악성 LDAP 서버와 HTTP 헤더 기반 JNDI 페이로드 전송 시나리오를 구성했습니다.
  • Verification: 원격 코드가 대상 환경에서 실행되는 흐름을 컨테이너 환경에서 검증했습니다.

주요 성과 및 인사이트

  • 취약한 Log4j 환경을 구성하고 JNDI 기반 RCE 공격 흐름을 검증했습니다.
  • `${lower:j}ndi` 형태의 우회 페이로드를 통해 단순 문자열 차단의 한계를 확인했습니다.
  • 오픈소스 라이브러리 취약점 관리와 조기 패치 체계의 중요성을 정리했습니다.

프로젝트 소개

Vuln-Camp는 Spring Boot + Next.js 기반의 이커머스 아키텍처를 직접 설계·구현한 Vulnerable-by-Design 웹 애플리케이션입니다. 상품 조회, 장바구니, 결제, 쿠폰, 고객센터(QnA), 공지사항, 마이페이지 흐름에 실제 웹 취약점 진단 시나리오를 녹여 구현했습니다.

모의해킹 결과보고서 기준 총 11건의 취약점을 진단하였으며, SQL Injection, SSRF, 파일 업로드·다운로드, 프로세스 검증 누락, 불충분한 인가, Stored XSS, CSRF, 정보 누출, 서버 정보 노출 항목에 대해 공격 절차와 보안대책을 정리했습니다.

기획 의도

단순 취약점 재현이 아니라, 설계자 겸 방어자의 시각으로 취약점이 발생하는 구조적 원인을 이해하고 실무에 적용 가능한 방어 로직을 도출하기 위해 제작했습니다. 특히 프론트엔드와 백엔드 사이의 신뢰 경계(Trust Boundary)가 결제, 쿠폰, 권한 처리 과정에서 어떻게 무너지는지를 코드와 공격 흐름으로 확인하는 데 초점을 맞췄습니다.

진단 결과

  • 총 취약점: 11건
  • 위험도 분포: 상 5건, 중 5건, 하 1건
  • 주요 항목: SQL Injection, SSRF, 파일 업로드, 파일 다운로드, 프로세스 검증 누락, 불충분한 인가, XSS, CSRF, 정보 누출, 서버 정보 노출

수행 역할

  • 취약점 설계 및 구현: QnA, 결제, 쿠폰, 공지사항, 파일 처리 기능에 주요 웹 취약점을 직접 구현했습니다.
  • 공격 검증: Burp Suite와 브라우저 개발자 도구를 활용해 파라미터 변조, 쿠키 변조, XSS, CSRF, SSRF, 파일 업로드·다운로드 공격을 재현했습니다.
  • 보고서 작성: 취약점별 개요, 보안 위협, 공격 절차, 증적 이미지, 보안대책을 포함한 모의해킹 결과보고서를 작성했습니다.
  • 실행 환경 구성: Docker Compose 기반으로 프론트엔드와 백엔드를 쉽게 실행할 수 있도록 구성했습니다.

주요 성과 및 인사이트

  • 공격이 성립하는 조건과 방어가 실패하는 지점을 코드 레벨에서 동시에 확인했습니다.
  • 서버가 클라이언트 값을 신뢰할 때 결제 금액 조작, 쿠폰 우회, 관리자 권한 오남용으로 이어질 수 있음을 실증했습니다.
  • 입력값 검증, 권한 검증, 파일 처리, CSRF 방어, 서버 측 비즈니스 로직 검증에 대한 보안 가이드를 정리했습니다.
